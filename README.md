# Director 3D

Инструмент создания 3D-анимации на движке **SAGE Engine**. Чистый C++17,
интерфейс на Dear ImGui, никаких скриптовых прослоек.

Идея простая: расставить объекты, поставить ключи, посмотреть, что получилось,
и вывести готовый ролик кадрами. Инструмент открывается в рабочем состоянии —
сцена с камерой, светом и полом уже собрана, и анимировать можно с первой
секунды.

---

## Что это такое

Director 3D — **отдельное приложение поверх движка**, а не его форк. Он линкует
ту же библиотеку `sage::engine`, что и игры с редактором SAGE, и добавляет свой
слой. Границы ответственности:

| Движок (SAGE Engine) | Director 3D |
|---|---|
| окно, ввод, главный цикл | таймлайн, кривые, ключи |
| рендер: батч, тени, PBR, пост-обработка | превью-вьюпорт и чистовой кадр |
| сцена и ECS, иерархия, сериализация | документ анимации и файл проекта |
| скелетная анимация (скелет, клипы, скиннинг) | раскладка клипов по времени |
| ресурсы, звук, физика | транспорт, отмена, экспорт секвенции |

Из этого следует практичное: сцену, собранную в Director 3D, можно выгрузить в
формат движка (`.sage`) и открыть в редакторе SAGE или загрузить в игру.

---

## Сборка

Нужны CMake ≥ 3.18, компилятор с C++17 и заголовки OpenGL/X11.

```bash
# Ubuntu/Debian
sudo apt install cmake g++ ninja-build libx11-dev libxrandr-dev \
                 libxinerama-dev libxcursor-dev libxi-dev libgl1-mesa-dev
```

Движок ищется автоматически: сначала явный путь, потом соседний каталог, потом
скачивается с GitHub.

```bash
# Обычный случай: SAGE-Engine лежит рядом с Director3D
git clone https://github.com/AmckinatorStudios/SAGE-Engine.git
git clone https://github.com/AmckinatorStudios/Director3D.git
cd Director3D

cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
./build/Director3D
```

Явный путь к движку, если он лежит не рядом:

```bash
cmake -B build -DSAGE_ENGINE_DIR=/путь/к/SAGE-Engine
```

Первая конфигурация скачивает зависимости движка (GLFW, GLM, EnTT, Jolt, Lua,
nlohmann/json) — это единственный шаг, которому нужна сеть.

### Запуск

```bash
./build/Director3D                    # новая сцена
./build/Director3D shot.d3dproj       # сразу открыть проект
./build/Director3D --self-test        # самотест ядра, без окна и OpenGL
```

Для вывода в MP4 нужен **ffmpeg** в `PATH`; без него доступна секвенция PNG.

## С чего начать

1. **Выберите объект** — в дереве сцены слева или кликом во вьюпорте.
2. **Поставьте ключ**: кнопка `Key` на панели инструментов (или клавиша <kbd>K</kbd>).
   Появится дорожка на таймлайне.
3. **Перетащите головку** таймлайна на другой кадр, подвиньте объект гизмо и
   поставьте ключ снова.
4. **Нажмите пробел** — объект поедет между ключами.
5. **`Render`** — получится файл `render/frame.mp4` (или секвенция PNG,
   если так выбрано в `Render > Render Settings`).

Быстрее всего — включить **Auto Key** (красный кружок на панели): тогда любая
правка объекта сама ставит ключ на текущем кадре, и ключить руками не нужно.

### Простой и продвинутый режим

Переключатель в правом верхнем углу. **Simple Mode** (по умолчанию) прячет
редактор кривых, Dope Sheet и тонкие параметры — остаётся ровно то, что нужно,
чтобы сделать анимацию. **Advanced** открывает всё: касательные, режимы
интерполяции, покадровый тайминг.

## Интерфейс

```
┌──────────────────────────────────────────────────────────────────────────┐
│ File Edit Create View Tools Animation Render Window Help                 │
├──────────────────────────────────────────────────────────────────────────┤
│ New Open Save │ Import Export │ Undo Redo │ Select Move Rotate Scale │ … │
├───────────┬──────────────────────────────────────────┬───────────────────┤
│  Scene    │  Viewport │ Render View                  │ Properties │ World│
│  дерево   │                                          │  трансформ,       │
│  объектов │        3D-сцена, гизмо, рамка кадра      │  камера, свет,    │
│           │                                          │  пост-обработка   │
├───────────┤                                          │  + ромбы ключей   │
│  Assets   ├──────────────────────────────────────────┤                   │
│  браузер  │  Transport: ⏮ ⏪ ▶ ⏩ ⏭  таймкод  fps      │                   │
│  файлов   ├──────────────────────────────────────────┤                   │
│           │  Timeline │ Graph Editor │ Dope Sheet     │                   │
├───────────┴──────────────────────────────────────────┴───────────────────┤
│ версия · GPU · память · FPS · проект · автосохранение                    │
└──────────────────────────────────────────────────────────────────────────┘
```

**Scene** — объекты, разложенные по категориям (Cameras / Characters /
Environment / Lights / Effects). Категории не хранятся в файле, а выводятся из
состава компонентов: навесили свет — объект сам переехал в Lights. Глазок
скрывает объект, перетаскивание меняет родителя.

**Viewport** — рабочий вид: свободная камера, сетка, каркасы камер и света,
манипулятор, подсветка выделения, рамка кадра активной камеры с затемнением
того, что в ролик не попадёт.

**Render View** — чистовой кадр от активной камеры в её соотношении сторон:
ровно то, что уйдёт в файл.

**Timeline** — дорожки с ключами, блоки скелетных клипов и звуковая волна.
**Graph Editor** — кривые значений с ручками касательных; кривая рисуется
сэмплированием, поэтому на экране видна та самая форма, по которой считается
движение. **Dope Sheet** — только тайминг, максимально плотно.

**Properties** — свойства выбранного объекта. У каждого анимируемого свойства
справа ромб: пустой контур — дорожки нет, тусклый — дорожка есть, но не на этом
кадре, яркий — ключ здесь. Клик ставит или убирает ключ. Это главный способ
анимировать что угодно, не открывая таймлайн.

## Возможности

### Анимация
- Ключи на позиции, повороте, масштабе, цвете, параметрах света и камеры,
  силе эффектов, видимости.
- Векторные свойства разложены по каналам: X, Y и Z ключатся независимо.
- Интерполяция: ступенька, линейная, авто-сглаживание (Catmull-Rom), Безье с
  ручными касательными, плавный старт / плавная остановка / оба.
- Скелетные клипы персонажей раскладываются блоками по времени с кросс-фейдом
  между ними; блок тянется мышью, края меняют длительность.
- Метки времени, прилипание к кадрам (<kbd>Alt</kbd> отключает).
- Auto Key: правка объекта сама ставит ключи.

### Персонажи и скелет
- **Анимация костей руками**, а не только проигрывание готовых клипов: кость
  выбирается в дереве сцены или кликом прямо во вьюпорте, правится гизмо и
  ключится как любое другое свойство. Скелет виден поверх картинки — суставы,
  связи, имя кости под курсором; кость с дорожкой подсвечена.
- Ручная поза кладётся **поверх клипа**, покостно и по каждому каналу отдельно:
  можно взять готовую ходьбу и доработать поворот головы, не трогая ноги. Кость
  без правки продолжает вести клип.
- Значения локальные — относительно родительской кости, в тех же градусах и в
  том же порядке осей, что у Transform объекта: «повернуть кость на 30°» и
  «повернуть объект на 30°» значат одно и то же.
- `Заключить позу` ставит ключи на всю тронутую позу разом, `Сброс` возвращает
  кость (или весь скелет) под управление клипа.
- **Блендшейпы** (морф-цели модели) — ползунки весов в инспекторе с теми же
  ромбами ключей: мимика анимируется так же, как всё остальное. Имена целей
  берутся из файла модели.

### Сцена
- Камеры, точечный и конусный свет, примитивы, персонажи, эмиттеры частиц, группы.
- Импорт `.glb` / `.gltf` (со скелетом и клипами) и `.obj`.
- Иерархия родитель–потомок, множественное выделение, дублирование.
- Заготовки: трёхточечная схема света, камера с полом, вращение объекта.

### Мир
- Небо двумя способами: процедурный градиент (зенит/горизонт) и **кубическая
  карта** из шести граней (`px/nx/py/ny/pz/nz`) — любой HDRI-панорамный набор.
  Яркость и поворот неба настраиваются, поворотом ставится нужное солнце «за
  кадром». Всё это — в панели **World**, там же солнце, ambient и туман.
- Небо участвует и в превью, и в Render View, и в экспорте — одним и тем же
  кодом, поэтому картинка везде одна.

### Кадр
- Полное освещение движка: солнце с тенями, точечные источники и прожекторы,
  полусферический ambient, туман.
- Пост-обработка: тон-маппинг, bloom, SSAO, виньетка, цветокоррекция,
  **глубина резкости**, **смаз движения**, **хроматическая аберрация**.
- Глубина резкости считается по кругу нерезкости из глубины: дистанция фокуса и
  диафрагма анимируются, поэтому перевод фокуса с плана на план ставится
  ключами. Есть автофокус — наводится на объект в центре кадра.
- Композиционные направляющие: рамка кадра, безопасная зона, сетка третей.
- Режимы просмотра: Shaded, Wireframe, Unlit, Normals.

### Вывод
- **Сглаживание накоплением**: чистовой кадр снимается несколько раз с
  микросдвигом проекции и усредняется. Это настоящий сверхсэмплинг — убирает и
  лесенку на кромках, и мерцание тонких деталей, чего экранный фильтр во
  вьюпорте не умеет в принципе. Время рендера растёт во столько же раз, поэтому
  число выборок задаётся в настройках рендера явно.
- **Готовый ролик MP4 (H.264)** — кадры уходят кодировщику потоком, без
  промежуточных файлов; звуковая дорожка проекта вшивается в тот же файл.
  Качество задаётся CRF, файл пишется с `+faststart` и в `yuv420p`, то есть
  открывается везде, включая браузеры и QuickTime.
- **Секвенция PNG** — без потерь, принимается любым монтажным пакетом и работает
  там, где ffmpeg не установлен.
- Разрешение и диапазон не зависят от размера окна и скорости машины: каждый
  кадр ставится по времени точно, поэтому результат воспроизводим.
- Экспорт сцены в формат движка (`.sage`).

> Для MP4 нужен **ffmpeg** в `PATH` (`apt install ffmpeg` / `brew install ffmpeg` /
> `winget install ffmpeg`). Если его нет, диалог рендера честно об этом говорит и
> предлагает секвенцию PNG.

## Устройство исходников

```
src/
  main.cpp              точка входа (движок даёт main через SAGE_MAIN)
  DirectorLayer.*       приложение как слой движка; реализует DirectorHost
  SelfTest.*            самотест ядра без окна и GL

  anim/                 модель данных анимации — без UI и без GL
    Curve.*             ключи, режимы интерполяции, вычисление значения
    Binding.*           «какое свойство какой сущности» — чтение и запись
    AnimationDocument.* дорожки, блоки клипов, метки, применение к сцене
    Playback.*          головка, проигрывание, таймкод
    AudioTrack.*        разбор WAV и огибающая для волны
    BonePose.*          кости: скелет сущности, чтение и правка локальной позы
    DirectorComponents.h свои ECS-компоненты (киношная камера, видимость, поза)

  project/
    Project.*           файл .d3dproj и снимки состояния
    UndoStack.*         отмена и повтор по снимкам

  render/
    StageRenderer.*     превью-вьюпорт и чистовой кадр
    SequenceExporter.*  вывод: ролик MP4 или секвенция PNG
    VideoWriter.*       поток кадров в ffmpeg, сборка команды кодировщика

  ui/
    Theme.*             палитра и стиль
    Icons.*             векторные иконки (рисуются кодом, без файла шрифта)
    DirectorHost.h      контракт, через который панели говорят с приложением
    panels/             каждая панель — самостоятельный класс
```

Два принципа, которые держат это в порядке:

**`anim/` ничего не знает про интерфейс и графику.** Кривые, дорожки и документ
— чистые данные и математика. Поэтому они проверяются самотестом без окна и
переиспользуемы вне редактора.

**Панели общаются с приложением только через `DirectorHost`.** Панель владеет
своим состоянием (текст поиска, что тащат мышью, открытая вкладка) и не знает
ни про `DirectorLayer`, ни про соседей. Новая панель — это новый файл в
`panels/` плюс один вызов в кадре.

## Форматы файлов

| Расширение | Что это |
|---|---|
| `.d3dproj` | Проект: сцена + анимация + настройки монтажа, один JSON |
| `.sage` | Сцена движка (экспорт и импорт) |
| `.glb` `.gltf` `.obj` | Модели |
| `.wav` | Звуковая дорожка с волной на таймлайне |
| `.mp4` | Готовый ролик H.264 (результат рендера) |
| PNG-секвенция | Покадровый результат рендера |

Сцена внутри `.d3dproj` сохраняется движковым сериализатором — тем же кодом и в
том же формате, что и `.sage`. Director 3D добавляет сверху свои разделы
(`director`, `animation`, `timeline`), которые движок просто не видит.

Проект — один файл, а не пара «сцена + анимация»: анимация ссылается на объекты
сцены по идентификаторам, и разъехавшиеся половинки давали бы молча сломанный
проект.

## Проверки

```bash
# Ядро анимации: кривые, дорожки, документ, транспорт, отмена, файл проекта,
# разбор WAV. Без окна и без OpenGL — работает на любой машине и в CI.
./build/Director3D --self-test

# Сквозная проверка на живом GPU: демо-анимация → рендер → сверка результата.
# Формат берётся по умолчанию (MP4, если найден ffmpeg). Под xvfb работает и
# без видеокарты.
cd build && D3D_SMOKE_TEST=1 xvfb-run -a ./Director3D

# Тот же прогон, но явно по каждому пути вывода.
cd build && D3D_SMOKE_TEST=1 D3D_SMOKE_FORMAT=mp4 xvfb-run -a ./Director3D
cd build && D3D_SMOKE_TEST=1 D3D_SMOKE_FORMAT=png xvfb-run -a ./Director3D

# Ручная анимация костей на ЖИВОМ скелете: выбрать кость -> согнуть -> убедиться,
# что поехал ребёнок -> два ключа -> перемотка между ними -> сброс позы.
# Headless-самотест сюда не достаёт: скелет приезжает вместе с моделью, а она
# требует графического контекста.
cd build && D3D_BONE_TEST=1 xvfb-run -a ./Director3D
```

### Переменные окружения

Нужны проверкам и отладке — в обычной работе не требуются.

| Переменная | Что делает |
|---|---|
| `D3D_WINDOW_WIDTH` / `D3D_WINDOW_HEIGHT` | Размер окна |
| `D3D_DEMO` | Наполнить проект демонстрационной анимацией |
| `D3D_ADVANCED` | Стартовать в продвинутом режиме |
| `D3D_TIMELINE_TAB` | Стартовая вкладка: `0` Timeline, `1` Graph, `2` Dope |
| `D3D_SCREENSHOT_AT_FRAME` / `D3D_SCREENSHOT_PATH` | Снять окно на кадре и выйти |
| `D3D_SMOKE_TEST` | Сквозная проверка рендера и выход |
| `D3D_SMOKE_FORMAT` | Формат сквозной проверки: `mp4` или `png` |
| `D3D_BONE_TEST` | Сквозная проверка костей на живом скелете и выход |
| `D3D_CHARACTER` | Создать персонажа и выбрать кость с этим индексом |
| `D3D_CHARACTER_KEYS` | Поставить на неё пару ключей (для снимков) |
| `D3D_SMOKE_SAMPLES` | Число выборок сглаживания в сквозной проверке |

Сборка с `-DD3D_PROFILE_FRAME` добавляет в лог время фаз кадра (тени, вьюпорт,
чистовой кадр с интерфейсом).

### CI и доступ к репозиторию движка

Director 3D не собирается без движка, а движок лежит в **другом репозитории**.
Токен раннера по умолчанию (`GITHUB_TOKEN`) выдаётся только на текущий
репозиторий, поэтому, **если SAGE-Engine приватный**, для CI нужен секрет
`SAGE_ENGINE_TOKEN` — PAT или токен GitHub App с правом чтения
`AmckinatorStudios/SAGE-Engine`. Заводится в
`Settings > Secrets and variables > Actions` репозитория Director3D. Если
движок публичный, секрет не нужен.

Workflow сначала берёт в движке ветку с **тем же именем**, что и текущая
(движок и инструмент развиваются парными ветками, и правку API движка надо
проверять вместе с её использованием), а если такой ветки нет — ветку движка по
умолчанию.

## Известные ограничения

Честный список того, чего пока нет. Что с этим делать и в каком порядке —
в [ROADMAP.md](ROADMAP.md).

- **Смаз движения — только камерный.** Смазывается движение и поворот камеры;
  быстро летящий мимо объект при неподвижной камере смаза не получит. Для этого
  нужен буфер скоростей на этапе геометрии, а не экранная репроекция.
- **Звук синхронизирован приблизительно**: движок не даёт посэмпловой привязки к
  головке. Волна на таймлайне при этом точна — по ней и расставляются ключи.
- **Волна строится только для WAV** (PCM 8/16/24/32 и float32). Файлы других
  форматов проигрываются, но показываются ровной линией.
- **MP4 пишется через внешний ffmpeg**, своего кодека в программе нет: H.264 —
  это отдельная большая зависимость с патентными оговорками. Без ffmpeg
  доступна секвенция PNG.
- **Небо из кубической карты берётся шестью изображениями**; развёртки
  «крест» и равнопрямоугольные `.hdr`-панорамы пока не разбираются — их надо
  предварительно нарезать на грани.
- **Обратной кинематики (IK) нет**: кости правятся прямой кинематикой, поэтому
  поставить ногу на пол — это разворот трёх костей вручную на каждом ключе.
- **Ручная поза не экспортируется в клип движка**: она живёт в `.d3dproj` и
  применяется поверх клипов. Отдать её игре как готовую анимацию пока нельзя.
